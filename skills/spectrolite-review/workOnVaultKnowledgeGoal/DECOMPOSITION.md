## Renderer boundaries and ambiguous links

Use exact renderer text, live wiki target and resolved destination, and preview phase as separate evidence. A link repair can change destination while keeping the public label and surrounding prose. Verify the actual before and after renderer link attributes as well as the independently persisted source. A literal link inside fenced code is evidence about source, with no navigation target.

The existing inline preview shows compile-stage and render-stage failures separately. Review the produced error card and its original detail. When a goal authorizes recovery, re-read the corrected source and the rendered component before handing off the working revision. An unrenderable document can only produce a held handoff.
